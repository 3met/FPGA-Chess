# Evaluation Tuning

Run `python -m tools.tuning train` to fit the material/PST PyTorch model from the configured local Lichess JSONL or JSONL.ZST dataset. Pass `--config path.json` to any action; otherwise `tools/tuning/default_config.json` is used. Install the optional toolchain with `python -m pip install -r requirements-tuning.txt`.

Training writes reusable caches, logs, checkpoints, parameters, metrics, and an atomically updated report under ignored `work/tuning/`. Cache construction reports progress at a configurable interval and automatically uses the estimated physical-core count; each cache keeps its own `build.log`. Training uses vectorized memory-mapped batches, derives PyTorch concurrency from available CPUs, and stops by optimizer step rather than dataset pass. `training.early_stopping_patience` is the number of non-improving validation passes allowed; set it to `null` to run through `max_steps`. It never changes engine values. `python -m tools.tuning view-report` summarizes the latest ongoing run; interrupted reports label current parameters separately and show the best-checkpoint export candidate. `python -m tools.tuning engine-commit [--dry-run]` exports the latest run only when it completed; when the latest run is interrupted, pass `--run ID` to deliberately export its best checkpoint. Every engine commit prints its selected run ID before modifying `hardware/data/pst_values/pst_values.json` and regenerating hardware data.

Material and PST are separate PyTorch parameter groups and start from zero knowledge: pawn material is fixed at 100 cp (128 engine units), king material is fixed at 0, knight through queen material starts at 0, and every PST starts at 0. No material prior, bounds, or ordering assumptions are applied. Knight-through-queen PST offsets are projected to symmetric extrema after each update; the king PST is likewise centered because its common offset cancels in every legal position. Pawn PST entries on unreachable ranks one and eight are fixed at zero, while reachable pawn PST entries are not centered. Dataset filtering rejects invalid or terminal standard-chess positions and missing PVs. `remove_in_check` applies to the root position; `remove_captures` and `remove_checks` apply only to the first move of the chosen PV. WandB is optional and disabled by default. New static-evaluation terms should be added as named model parameter groups and corresponding engine exporters.
