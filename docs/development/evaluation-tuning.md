# Evaluation and NNUE Tuning

Run `python -m tools.tuning train` to fit the material/PST plus NNUE PyTorch model from the configured local Lichess JSONL or JSONL.ZST dataset. Pass `--config path.json` to any action; otherwise `tools/tuning/default_config.json` is used. Install the optional toolchain with `python -m pip install -r requirements-tuning.txt`.

Training writes reusable caches, logs, checkpoints, parameters, metrics, and an atomically updated report under ignored `work/tuning/`. Cache construction reports progress at a configurable interval and automatically uses the estimated physical-core count; each cache keeps its own `build.log`. Training uses vectorized memory-mapped batches and fuses NNUE feature gather/reduction with PyTorch embedding-bag on both CPU and CUDA, avoiding a large temporary tensor. CUDA additionally uses pinned nonblocking transfers, while CPU uses the configured PyTorch worker count directly. Training stops by optimizer step rather than dataset pass. `training.early_stopping_patience` is the number of non-improving validation passes allowed; set it to `null` to run through `max_steps`. It never changes engine values. Pass `--initialize RUN` to start a new run from another run's best model with a fresh optimizer; the former version-six two-head model is projected onto the exact antisymmetric difference head during this transition. `python -m tools.tuning view-report` summarizes the latest ongoing run; interrupted reports label current parameters separately and show the best-checkpoint export candidate. `python -m tools.tuning engine-commit [--dry-run]` exports the latest run only when it completed; when the latest run is interrupted, pass `--run ID` to deliberately export its best checkpoint. Every engine commit prints its selected run ID before modifying `hardware/data/pst_values/pst_values.json` and regenerating hardware data. Export requires material values to fit signed 16-bit engine units and PST offsets to fit signed 10-bit engine units; training itself remains unbounded.

Material and PST are separate PyTorch parameter groups and start from zero knowledge: pawn material is fixed at 100 cp (128 engine units), king material is fixed at 0, knight through queen material starts at 0, and every PST starts at 0. No material prior, bounds, or ordering assumptions are applied. Knight-through-queen PST offsets are projected to symmetric extrema after each update; the king PST is likewise centered because its common offset cancels in every legal position. Pawn PST entries on unreachable ranks one and eight are fixed at zero, while reachable pawn PST entries are not centered.

The NNUE correction starts at zero with live quantized parameters: accumulator bias starts at one, every pair of transformer channels starts from the same deterministic sparse ternary row, and their alternating plus-one/minus-one output weights cancel exactly. This gives the transformer, accumulator bias, and output layer useful straight-through gradients while their initial summed correction remains zero. Its forward pass quantizes the 768-by-256 direct two-side, six-piece, 64-square transformer, builds both vertically oriented perspectives, reduces state modulo signed six-bit range, applies ReLU clipped at 31, subtracts the Black activation from the White activation lane by lane, and evaluates one shared direct output layer without an output bias. The difference head makes the correction exactly color-antisymmetric. The integer MAC result is converted from the hardware's pawn/128 score units to centipawns for the training loss, so exported signed-int4 weights require no rescaling. Engine export writes the transformer as 64-byte rows with four signed two-bit ternary weights per byte and writes the output as two 128-weight nibble rows. NNUE export uses ties-to-even rounding to match `torch.round` in the quantization-aware forward pass. Accumulator bias is constrained to signed three-bit range and written as one hexadecimal digit per lane.

NNUE checkpoints carry a numerical-model version. Runs created before the live initialization, pawn/128 scaling correction, or single-output-layer format are rejected by resume and export instead of being silently interpreted with incompatible units or tensor shapes.

Dataset filtering rejects invalid or terminal standard-chess positions and missing PVs. `remove_in_check` applies to the root position; `remove_captures` and `remove_checks` apply only to the first move of the chosen PV. WandB is optional and disabled by default.
