# Search-Parameter Tuning

`python -m tools.search_tuning run` tunes the synthesized search policy against Stockfish. It starts by measuring `hardware/config/search/default.json`, then uses a local additive Gaussian-process trust-region search to spend substantial CPU time selecting each subsequent trial. The acquisition search works on configured integer, rational, and fixed-point-aligned grids and maximizes expected Elo improvement near the model's posterior-best configuration. This search center is intentionally separate from the more conservative configuration published to `best.json`.

The default configuration is `tools/search_tuning/default_config.json`. It enables all 39 semantic parameters, evaluates 50 configurations with 500 paired openings each, synthesizes and programs `quartus-de1-soc`, and runs the shared [Stockfish benchmark](stockfish-benchmark.md) with full-strength Stockfish and a fixed node budget. The node budget inherits the benchmark default unless `stockfish_nodes` is set in the tuning configuration. The benchmark runner creates and resumes Fastchess autosaves directly. Copy the configuration before changing iteration count, match length, progress interval, executable paths, parameter selection, safe range overrides, synthesis jobs, or optimizer effort. Iteration count, progress frequency, synthesis jobs, and acquisition-pool sizes may change on resume; changes to parameters or experiment semantics require a new output directory.

Run `python -m tools.search_tuning run --dry-run` to validate the setup and create the first candidate without synthesizing or programming hardware. Run `python -m tools.search_tuning status` for a compact progress report. After changing RTL, engine behavior, or other experiment semantics, run `python -m tools.search_tuning run --clean` to archive the existing output under a sibling `-archive` directory and begin again from the current baseline. A normal run prints phase timing, periodic game counts, and final trial ratings; detailed synthesis, programming, and tournament output is retained under `work/search-tuning/logs/`.

The tuner never writes `default.json`. The current trial is `work/search-tuning/candidate.json`, the strongest completed trial is `work/search-tuning/best.json`, and immutable trial snapshots are stored under `work/search-tuning/trials/`. A generated engine profile points synthesis at the candidate without changing the tracked DE1-SoC profile.

State is validated and atomically checkpointed after every phase and protected by a single-run lock. Re-running the same command resumes interrupted synthesis through Quartus Smart Recompile, skips already completed synthesis or programming phases, and resumes an interrupted Fastchess tournament from its autosaved state. Programming requires a successful synthesis receipt matching the exact bitstream, so a failed build can never expose an older image as the current candidate. The tuner tries each configured fitter seed before rejecting a synthesis-infeasible candidate; these rejections are excluded from later proposals but never enter the Elo model or consume a measured iteration. It stops after `maximum_synthesis_rejections` to avoid wasting resources on a systemic timing problem. Before a normal or dry run, a preflight check verifies build and programming targets, vendor tools, benchmark executables, and the opening book. The experiment fingerprint covers relevant RTL, engine software, build inputs, the shared benchmark runner and binaries, Stockfish, and the opening book so incompatible measurements cannot be mixed silently.

Fastchess Elo is noisy, so the surrogate converts its reported 95% confidence interval to a standard deviation and applies a configured noise floor. Every ordinary trial contributes one match and immediately releases the optimizer to explore another parameter set. After all configured trials, the tuner greedily selects strong GP-posterior candidates while enforcing parameter-space diversity. It then runs the baseline and finalists on identical disjoint opening blocks, estimates paired Elo differences including their measured covariance, and allocates another block only to unresolved candidates with sufficient probability of improvement. `best.json` changes only when a paired result clears `validation.promotion_z_score`; `provisional.json` contains the most promising validated challenger, and `report.json` records posterior rankings, paired results, infeasible trials, and parameter consensus. Validation games do not count as configured exploration iterations.

After the baseline, ordinary challenger matches use Fastchess's native logistic pentanomial SPRT as a one-sided futility test. By default its hypotheses are set relative to the incumbent's conservative lower confidence bound: 40 Elo and 15 Elo below that bound, with alpha 0.10 and beta 0.02. An H0 decision rejects a demonstrably inferior candidate early and enters the surrogate as a conservative upper-censored observation while retaining the raw result for auditing. An H1 decision disables SPRT in the saved Fastchess checkpoint and immediately resumes that same match to the configured game count, so every game remains part of one fixed-length estimate and viable candidates incur only negligible process-restart overhead. Validation matches always run for the configured game count. Configure or disable futility testing with `early_stopping`.

Fastchess timeout and crash totals are recorded for every tournament. A trial exceeding `runtime_failures.maximum_per_tournament` remains in the audit history but is excluded from the Elo surrogate, promotion, and validation because disconnect-heavy results describe infeasibility rather than playing strength. Synthesis-infeasible candidates remain separate rejections. Ambiguous optimizer outcomes preserve accumulated trust-region evidence instead of resetting it, allowing the radius to adapt under noisy measurements.

The initial design perturbs one related parameter group at a time and chooses maximin points from a rotated Halton pool at a fixed radius. After every group has been sampled, the tuner fits a group-additive Gaussian-process surrogate and performs expected-improvement acquisition inside the adaptive trust region. Later candidates modify four parameter axes on average by default, limiting confounded high-dimensional jumps with only tens of observations.
